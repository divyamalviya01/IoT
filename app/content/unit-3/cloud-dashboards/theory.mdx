<Callout kind="definition" title="In one line">
A cloud dashboard is a screen of widgets that shows live IoT data at a glance, raises alerts when something goes wrong and lets people control devices.
</Callout>

## What a dashboard is for

Raw sensor data is a long list of numbers. Nobody can watch it. A <Term id="dashboard">dashboard</Term> turns it into pictures that answer questions quickly: *Is the cold room cold enough? Where is the van? Did the pump turn on?*

Each block on the screen is a <Term id="widget">widget</Term>, bound to one data stream.

## Getting live data to the screen

A dashboard must show the newest data. There are two ways to get it.

  caption="Polling vs push"

<Term id="polling">Polling</Term> is simple but wasteful: 100 widgets polling every 5 seconds make 20 requests a second, even on a quiet night. A <Term id="websocket">WebSocket</Term> keeps one connection open, so the server can push only real changes. Lab L21 counts the messages both ways.

## Controlling devices from a dashboard

A switch widget does not reach the device directly. It sets the **desired** state in the device's shadow (topic 3.3). The widget should show "turning on…" until the device **reports** that it is on. If the device is offline, the command waits.

## Good dashboard design

- **Know the question.** A factory manager and a maintenance engineer need different dashboards.
- **Most important at the top left,** where people look first: usually alerts and key figures.
- **Fewer widgets.** About 8 per screen; more and the important ones get lost.
- **The right widget for the data:** a map for locations, a line chart for trends, not gauges for everything.
- **Titles and units on everything:** "32 °C", not "32".
- **Colour only for meaning:** red, amber and green for status, always with an icon or word as well, so colour-blind users can read it.
- **Alerts with sensible limits:** add <Term id="hysteresis">hysteresis</Term> so an alert does not flash on and off as a value wobbles around the limit.
- **Show freshness:** "updated 5 s ago" tells people whether to trust the screen.
- **Works on a phone:** widgets stack into one column.

<Callout kind="remember" title="Hysteresis in one example">
An alert turns on above 35 °C. Without hysteresis, a room at 34.9, 35.1, 34.9, 35.1 °C sends four alerts in four minutes. With 0.5 °C hysteresis, it turns on above 35 °C and only turns off below 34.5 °C, so it sends one.
</Callout>

## Dashboard tools

- **Grafana** (open source, AGPL-3.0): popular for time-series charts and alerts.
- **ThingsBoard** and **Node-RED Dashboard:** dashboards built into IoT platforms and flow tools.
- **ThingSpeak:** quick charts of channel data, with MATLAB analysis.
- **Business tools** such as Microsoft Power BI, for reports that mix IoT data with other company data.

<Callout kind="example" title="City command and control centres">
Under the Smart Cities Mission, many Indian cities run an Integrated Command and Control Centre. Large dashboards show traffic cameras, bus locations, water supply, streetlight faults and air quality on maps and charts. Alerts send staff to fix problems quickly.
</Callout>

## Advantages and limitations

**Advantages**

- Turns huge data into quick understanding.
- Spots problems early through alerts.
- Lets people control devices from anywhere.

**Limitations**

- A cluttered dashboard hides what matters.
- Polling dashboards waste data and show stale values.
- Too many alerts make people ignore them (alert fatigue).
- A dashboard is only as good as the data behind it.
