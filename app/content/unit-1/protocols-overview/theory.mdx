<Callout kind="definition" title="In one line">
IoT protocols are the agreed rules devices use to talk, arranged in layers from the radio up to the application; IoT software is the code that runs on devices, gateways and servers to use them.
</Callout>

## Why protocols come in layers

A <Term id="protocol">protocol</Term> is a set of rules for sending and understanding messages. Sending a sensor reading across the internet involves many jobs: choosing a radio channel, addressing the device, delivering the data and making sense of it.

No single protocol does all of this. Instead, protocols are stacked in layers. Each layer does one job and uses the layer below it. This is called a protocol stack.

Layers can be swapped independently. The same MQTT application can run over Wi-Fi, Ethernet or 4G without changing a line of the application.

## Encapsulation: how layers wrap data

When data goes down the stack, each layer adds its own <Term id="header">header</Term> in front of it. This is called <Term id="encapsulation">encapsulation</Term>. It is like putting a letter in an envelope, the envelope in a parcel, and the parcel in a delivery van.

At the receiver, each layer removes its own header and passes the rest up.

<Callout kind="remember">
Headers are overhead: they are needed, but they are not your data. Small sensor readings can be smaller than their headers, which is why IoT protocols try to keep headers short.
</Callout>

## Why IoT needs its own protocols

Web protocols were designed for powerful computers on fast, reliable links. IoT devices are different:

- **Small memory and slow processors:** protocols must be simple to implement.
- **Batteries:** every extra byte sent costs energy, so headers must be short.
- **Lossy radio links:** packets go missing more often than on a cable.
- **Huge numbers of devices:** one server may talk to millions of devices.

So IoT uses lightweight protocols such as MQTT (2-byte minimum header) and CoAP (4-byte header). 6LoWPAN shrinks the 40-byte IPv6 header to a few bytes for tiny radios.

## IoT software

Protocols need software to run them. IoT software works at three places: on the device, on the gateway and in the cloud.

An <Term id="rtos">RTOS</Term> lets a small microcontroller run several tasks, such as reading a sensor and running the radio, on strict schedules. <Term id="middleware">Middleware</Term> sits between devices and applications and handles common jobs such as messaging and device management.

<Callout kind="example" title="A Wi-Fi smart plug">
An ESP32 inside the plug runs FreeRTOS. Its firmware publishes the power reading with MQTT, over TCP, over IPv4, over Wi-Fi. A Mosquitto broker on a home server receives it, and Node-RED switches the plug off when the geyser has been on for too long.
</Callout>

## Advantages and limitations of layering

**Advantages**

- Each layer can be designed, tested and replaced on its own.
- Different makers' products work together if they follow the same layer standards.
- The same application works over many kinds of network.

**Limitations**

- Every layer adds a header, so small messages carry a lot of overhead.
- More layers mean more processing on small devices.
- A problem can be hard to trace when it could sit in any layer.
