## What the differences mean

**Overhead.** MQTT and CoAP use compact binary headers. HTTP and XMPP send readable text and XML, so a 4-byte reading can travel with a hundred bytes or more of headers.

**Transport.** CoAP's UDP needs no connection, so a sleepy device can wake, send one packet and sleep. MQTT, HTTP, XMPP and AMQP need a TCP connection, which costs a handshake and keep-alive traffic.

**Pattern.** Publish–subscribe (MQTT, AMQP) lets one message reach many receivers and keeps senders and receivers independent. Request–response (HTTP, CoAP) is simpler when one client wants one answer.

**Reliability.** MQTT lets each message choose QoS 0, 1 or 2. CoAP chooses per message with CON or NON. HTTP and XMPP rely on TCP.

<Callout kind="remember">
A real system often uses several protocols: CoAP or Zigbee on the device network, MQTT from the gateway to the cloud, HTTP for the mobile app's API, and AMQP between cloud services.
</Callout>

## A quick way to decide

1. **Is the device very small, on a lossy, low-power network?** Prefer CoAP (or MQTT-SN).
2. **Do many receivers need the same data, or do devices send frequent telemetry?** Prefer MQTT.
3. **Is it an occasional upload or a web API for apps?** Prefer HTTP.
4. **Do you need presence and person-to-device messaging?** Consider XMPP.
5. **Is it business back-end messaging with queues?** Consider AMQP.

<Callout kind="example" title="A smart-city water network">
Flow meters in pipes use CoAP over a low-power mesh to report to street gateways. Gateways publish to the city's MQTT broker. The water board's billing system receives events through AMQP queues, and citizens see their usage through an HTTP API in a mobile app.
</Callout>
