<Callout kind="definition" title="In one line">
CoAP is a lightweight, web-like protocol for small devices: it uses GET, PUT, POST and DELETE on URLs like HTTP, but runs over UDP with a 4-byte binary header and adds its own simple reliability.
</Callout>

## What is CoAP?

<Term id="coap">CoAP</Term> (Constrained Application Protocol) was standardised by the IETF in 2014 as RFC 7252. It is designed for constrained devices: small microcontrollers with kilobytes of memory on lossy, low-power networks.

CoAP copies the good ideas of the web. Every sensor value is a resource with a URL such as `coap://sensor.local/temp`, and clients use familiar methods. This makes it easy to translate CoAP to HTTP at a gateway.

CoAP runs over UDP on port 5683, or port 5684 when secured with <Term id="dtls">DTLS</Term>.

### When a message is lost

If no ACK arrives, the client waits and resends. The first wait is 2 to 3 seconds, and it doubles after every try. After 4 retries, the client gives up.

## Special features

- **<Term id="observe">Observe</Term>:** a client sends GET with the Observe option once. The server then sends a notification every time the resource changes, with no polling.
- **Resource discovery:** `GET /.well-known/core` returns a list of the device's resources, so a client can find out what a new device offers.
- **Block-wise transfer:** large data, such as a firmware image, is split into numbered blocks that fit small packets.
- **Multicast:** one request can reach every device in a group, such as "all lights on floor 2".
- **Proxies:** a gateway can translate between CoAP and HTTP, so web apps can reach CoAP devices.

<Callout kind="example" title="Smart street lights">
Street-light controllers on a 6LoWPAN mesh run CoAP servers. The city's gateway observes `/status` on each light, gets a notification only when a lamp fails, and uses a multicast PUT to dim a whole street at midnight.
</Callout>

## Advantages and limitations

**Advantages**

- Tiny 4-byte header and no connection setup: ideal for small devices and lossy radios.
- Familiar REST model; easy to map to HTTP.
- Choose reliability per message with CON or NON.
- Observe gives server push; multicast reaches groups of devices.

**Limitations**

- UDP traffic is sometimes blocked by firewalls and home routers.
- Built-in reliability is simple: no flow or congestion control like TCP.
- DTLS security adds a handshake and extra bytes.
- Fewer cloud services support it directly than MQTT or HTTP.
