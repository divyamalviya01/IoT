<Callout kind="definition" title="In one line">
An IoT architecture splits the system into layers, from the sensors at the bottom to the user's application at the top, and each protocol works at one layer, using the layer below and serving the layer above.
</Callout>

## Why use layers?

An IoT system is too big to design as one piece. Layers split it into jobs that can be built and changed separately. A farmer's app does not care whether the soil sensor uses LoRa or Wi-Fi, as long as the layer below delivers the reading.

Each layer offers services to the one above and uses the one below. Two devices talk layer to layer: the application on the sensor talks to the application on the server, through all the layers underneath.

### The IETF stack for constrained devices

The Internet Engineering Task Force (IETF) designed a full IP stack for tiny battery devices. Each layer swaps a heavy internet protocol for a light one:

<LayerStack
  caption="IETF constrained-device stack"
  layers={[
    { name: "Application: CoAP", detail: "REST like HTTP, but with a 4-byte binary header instead of text headers.", items: ["Replaces HTTP"] },
    { name: "Transport: UDP", detail: "No handshake and an 8-byte header, which saves battery.", items: ["Replaces TCP"] },
    { name: "Network: IPv6 + RPL", detail: "IPv6 gives every sensor its own address. RPL is a routing protocol that finds routes through the low-power mesh; it adds no header of its own to each reading.", items: ["Enough addresses for billions of things"] },
    { name: "Adaptation: 6LoWPAN", detail: "Compresses the 40-byte IPv6 header to a few bytes and splits large packets, so they fit in 127-byte radio frames.", items: ["Header compression", "Fragmentation"] },
    { name: "Link + physical: IEEE 802.15.4", detail: "A low-power radio at 250 kbit/s with small frames. Zigbee and Thread use it too.", items: ["Replaces Wi-Fi or Ethernet"] },
  ]}
/>

<Term id="6lowpan">6LoWPAN</Term> is an <Term id="adaptation-layer">adaptation layer</Term>: it does not route or deliver anything itself, it adapts IPv6 to the small frames of <Term id="ieee-802-15-4">IEEE 802.15.4</Term>. <Term id="rpl">RPL</Term> builds the routes that IPv6 packets follow through the mesh.

The Visualize tab shows a reading travelling down a sender's stack, gaining a header at each layer, and up the receiver's stack, losing them again. Lab L14 asks you to place protocols in the right layers.

## The IoT-A reference model (an introduction)

<Term id="iot-a">IoT-A</Term> (Internet of Things – Architecture) was a European research project (2010–2013). It produced an **Architectural Reference Model**: a common set of names and views that any IoT system can be described with. It includes:

- **Domain model:** the users, physical things, devices, resources and services, and how they relate.
- **Information model:** how data about things is structured.
- **Functional model:** groups of functions such as device, communication, IoT service, virtual entity, service organisation, process management and application, with management and security running across all of them.
- **Communication model:** how parts exchange information.
- **Trust, security and privacy model:** studied in Unit 3 (topics 3.12 and 3.13).

<Callout kind="example" title="A smart streetlight, layer by layer">
A light sensor and an LED driver in the pole form the perception layer. The pole joins a mesh of other poles over IEEE 802.15.4 with 6LoWPAN and RPL, reaching a gateway that forwards data over 4G. The city's lighting platform (processing) dims lights on empty roads, and the control-room app (application) shows faults. The city's energy budget and maintenance contracts belong to the business layer.
</Callout>

## Advantages and limitations of layered architecture

**Advantages**

- Each layer can be designed, changed or replaced without rewriting the others.
- Standard interfaces let devices from different makers work together.
- Easier to teach, design and troubleshoot.

**Limitations**

- Extra headers at every layer add overhead, which matters on small radios.
- Strict layering can hide information that would help save energy.
- Different books use different models (3, 4, 5 or more layers), which can confuse.
